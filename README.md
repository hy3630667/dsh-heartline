# dsh-heartline（心跳急救）

给这台 Windows 机器上的 DSH 桌面应用做自愈：崩了能自己起来，僵死能看出来，起不来能进急救模式把自己修回来。

作者：红。约束：单机、无人值守、不能依赖被守护对象自己。

## 目录

```
src/急救本体.ps1    外部判定器：看 DSH 死活（v0.1 只看不动手，只写证据）
src/deploy.ps1      部署脚本（必须由管理员通道执行，带健康检查与回滚）
docs/架构-v0.1.md   架构与判据
tests/              演练脚本（占位）
```

## 两个位置，别混

| | 在哪 | 谁可写 | 说明 |
|---|---|---|---|
| 仓库 | `D:\项目\dsh-heartline` | 我（普通权限） | 改代码、提交、打 tag |
| 部署位 | `C:\ProgramData\DSH-Heartline\` | 只有管理员 | 提权任务跑这里，普通用户不可写 |
| 运行时数据 | `C:\Users\28565\.dsh\heartline\` | 本体（管理员）写 | 心跳、判定、事件 |

**为什么不能从仓库直接跑**：本体要提权，提权任务执行一个普通用户能改的脚本，等于任何以这个用户身份跑的程序写一行就能拿管理员。所以部署位必须只管理员可写。

## 版本与更新

- 版本号写进 `src/急救本体.ps1` 的 `$版本`，同时出现在每份心跳的 `version` 字段里——从外面就能看出现在跑的是哪一版。
- 发布 = 打 tag：`git tag v0.2.0`。
- 部署 = 管理员通道跑 `src/deploy.ps1 -Tag v0.2.0`：检出 tag → 算哈希 → 顶替 current（旧的进 previous）→ 重启任务 → 90 秒看心跳版本与新鲜度 → 不合格自动回滚上一版。
- **不做自动更新**。提权的东西只在我发起、留痕的情况下更换，deploy.log 里记一条。

## 判据（v0.1）

每 10 秒一轮：进程数 0 → GONE；起来不到 180 秒 → STARTING；有窗口且控件树读得回 → ALIVE；探针超时且 CPU 零增量且不响应 → SUSPECT；其余（看不见、托盘、在忙）→ UNKNOWN。

**UNKNOWN 永远不触发动作。** 这一条是 2026-11-03 那次误杀换来的。
